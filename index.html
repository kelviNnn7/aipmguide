MODULE 01

AI基础技术认知

面试权重最高 · 转行者生死线

面试官不需要你推导公式，但必须能判断三件事："这个需求模型能不能做、做到什么程度、代价多大"。知识点按考察深度分级：L1 讲清概念 L2 举例讲为什么 L3 做权衡决策

  • 三大范式 L2：监督 / 无监督 / 强化学习的区别与典型应用（RLHF为什么属于强化学习）
  • 核心概念 L2：训练 / 验证 / 测试集、过拟合与欠拟合、损失函数、学习率的直觉
  • 经典模型 L1：逻辑回归、决策树、XGBoost——知道什么场景用什么即可
  • 深度学习结构 L1：神经网络分层、反向传播直觉、CNN / RNN适用场景
  • Embedding L3：文本 / 图片为何转向量、余弦相似度——理解推荐系统与RAG的钥匙，必考
🎯 高频追问
"模型过拟合了，作为产品经理你会怎么处理？"——正确答案不是技术细节本身，而是你能与算法团队对话：增加训练数据、简化模型、正则化、早停，并且知道先问"是训练集和线上分布不一致吗？"
⚠️ 扣分项
只会背定义。面试官会追问"你上一段经历里哪里用到了这个认知？"答不上来，前面背的全作废。
  • Transformer L2：自注意力机制的直觉（"每个词动态关注上下文中最相关的词"）、为何取代RNN（并行 + 长程依赖）
  • LLM训练全流程 L3：必考，务必能脱稿完整复述
    1. 预训练：海量语料 + 下一个词预测 → 基座模型（"博览群书但不懂规矩"）
    2. SFT监督微调：高质量指令数据教会模型"听懂人话"
    3. 对齐（RLHF / DPO）：让回答更有用、无害、诚实；知道DPO为何部分取代RLHF（更稳定、更便宜）
  • 推理侧概念 L3：Token与计费逻辑、Temperature / Top-p（创造性 vs 确定性）、上下文窗口、首Token延迟（TTFT）与生成速度（TPS）
  • 幻觉 L3：成因（本质是概率生成，不是数据库查询）与缓解手段（RAG、引用溯源、置信度外显、人工兜底）
  • RAG完整链路 L3：文档切分 → 向量化 → 检索（稠密/稀疏混合）→ 重排序（Rerank）→ 拼入Prompt → 生成。每个环节都能出一个追问
  • Agent L2：ReAct模式（思考-行动-观察循环）、Function Calling / Tool Use、多Agent协作的现状与坑（错误累积、不可控）
  • 推理模型 L2：o1 / R1类模型与普通模型的区别、Test-time Compute对产品设计的含义

三大增强路线选型（必背表）

路线解决什么问题成本不适用场景
Prompt Engineering约束输出格式与风格、注入少量知识几乎为零知识量大、需稳定复现
RAG 检索增强知识实时更新、可溯源、私有知识低（工程为主）改变模型"行为风格"
微调 SFT固化行为模式、领域术语、稳定格式高（数据 + 算力）知识频繁变化
🎯 面试官视角
"微调还是RAG"是经典题，但真正拉开差距的是后半句——"预算有限、两周上线，怎么办？"（答：先Prompt + MVP验证需求真伪，再决定投入）。面试官要的是成本意识与节奏感，不是标准答案。
  • CV核心任务 L1：分类、检测、OCR、分割的能力边界
  • 多模态大模型 L2：VLM原理直觉、文生图Diffusion基本原理、文生视频现状（可控性差、时长短、成本高）
  • 语音 L1：ASR的WER、TTS的MOS评分；实时语音通话的延迟构成（ASR + LLM + TTS三段叠加）

对每个技术方向，能回答三问：① 现在能做到什么 ② 做不到什么 ③ 成本曲线如何。

例如："LLM数学推理仍脆弱、幻觉不可根除只能缓解；推理成本每年大幅下降，GPT-4级别能力两年内降价超90%"——能讲出成本趋势，说明你懂商业化前提。

MODULE 02

AI产品方法论

需求分析：AI产品的三重验证

需求真实性痛点是否成立、频次多高、现有替代方案是什么
技术可行性当前模型能力能否支撑？90分可用、95分好用、99分才敢收费——"Demo惊艳"与"日常可用"之间有鸿沟
经济性单次调用成本 × 预期调用量，能否算得过账（用模块三的计算器练习）

效果兜底设计（AI产品特有，PRD必备一节）：模型答错时的产品策略——置信度阈值、降级方案、人工兜底、引用溯源让用户自查、免责声明。

模型评估与优化（区别于传统PM的核心能力）

第一层

客观指标

准确率、召回率、F1；生成类BLEU / ROUGE——知道含义与局限：与人工感受相关性弱

第二层

人工评测

标注规范设计、GSB对比评测（Good / Same / Bad）、Elo评分（竞技场模式）

第三层

LLM-as-Judge

大模型当裁判；注意位置偏差、长度偏好、自家模型偏好，需人工抽检校准

Badcase分析四步法（高频实操题）

分层抽样按场景 / 意图分层，避免只看头部case
归因分类数据问题 / Prompt问题 / 模型能力问题 / 产品设计问题
排优先级按 影响面 × 修复成本 排序
回归验证修复后跑评测集回归，确认无劣化
🎯 面试官视角
我必问："你怎么知道这个版本比上个版本好？"——能答出"离线评测集回归 + 小流量GSB人工评测 + 线上AB三层验证"的候选人，直接进入下一轮。

数据驱动与数据闭环

  • 北极星指标：AI产品特有指标——任务完成率、采纳率（Copilot类）、人工接管率（客服类）、会话深度
  • 数据闭环：用户行为（点赞 / 点踩 / 采纳 / 改写 / 重试）回流为评测集与训练数据。这是AI产品最深的护城河：竞品可以抄功能，抄不走你的用户反馈飞轮

A/B测试的AI特殊性

  • 模型输出有随机性，实验要控制Temperature
  • 离线指标涨但线上不涨 → 优先怀疑数据分布偏移
  • 模型迭代用影子测试 + 灰度发布平滑迁移

AI产品生命周期

阶段关键动作
0 → 1技术预研 → Prompt快速搭MVP验证 → 评测体系先行（先于功能开发）→ 小流量灰度
增长期成本优化（模型路由：简单问题走小模型、缓存命中、蒸馏小模型替换）、场景扩展
双迭代节奏产品功能迭代（确定性排期）与模型能力迭代（不确定性排期）协同——给算法探索留buffer，用"功能解耦模型版本"的架构降低互相阻塞

MODULE 04

跨团队协作能力

🧪 与算法工程师

  • 听懂黑话：Loss不收敛、分布偏移、模型漂移、Badcase归因
  • 需求翻译："回答太啰嗦" → "控制输出长度分布——SFT数据约束或系统提示词，两周内哪个可行？"
  • 预期管理：问"成功率多少、备选方案、最坏情况的兜底"

📊 与数据团队

  • 标注规范撰写、标注一致性抽检
  • 训练集 / 评测集配比与去重
  • 数据配比（领域 / 语言分布）对模型行为的影响

⚙️ 与工程团队

  • 推理服务架构、并发与限流、流式输出
  • 延迟构成：网络 + TTFT + TPS——用户喊"卡"时知道先查哪一环
🎯 行为面必考冲突题
"算法同学说你要的效果做不到，怎么办？"四步走：拆解需求（是否可降精度）→ 换技术路线（RAG不行试微调）→ 调整产品形态（全自动改人机协同）→ 都不通则砍需求并同步stakeholders。答出"调整产品形态"这一层的候选人极少，答出来就是亮点。

🏆 作品集：转行者的胜负手

一个动手作品（最重要）用扣子 / Dify搭Agent，或API + Cursor做AI小工具。必须能讲清：需求来源 → 技术选型 → Prompt设计迭代 → 评测方法 → Badcase改进。价值不在复杂，而在能复盘每个决策
一次评测实践对某AI产品做50–100条case的系统评测，输出Badcase归因报告——在智谱、Moonshot这类公司极其加分，因为这就是日常工作的样子

行业信息源机器之心、量子位、晚点LatePost；追每周新模型发布——能聊"上周XX发布的模型意味着什么"，直接证明你是圈内人
⚠️ 扣分项
简历写"熟悉大模型原理"但没有任何作品或输出物。面试官默认：没作品 = 没动手 = 学习意愿存疑。一份粗糙但真实的作品，胜过十条自我评价。

FINAL

面试官的最后三条忠告

1

建立"技术边界感"

AIPM与普通PM的分水岭。面对任何需求，第一反应是"模型现在能做到什么程度、成本多少、如何评估"。养成这个肌肉记忆，面试成功一半。

2

三层证明法

用作品证明意愿，用框架证明思维，用细节证明经验。转行者最大的翻盘武器是"做得比在职的人还认真"。
